## 2. 技術選定

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語 | Swift 6 ツールチェーン（言語モード 5） | Apple 純正。AppKit との相性 |
| ビルド | Swift Package Manager ＋ `scripts/build_app.sh` で .app 化 | テキストだけで管理でき差分が追いやすい。Xcode でも `Package.swift` を開ける |
| 表示 | AppKit（`NSPanel` 枠なし・透過・非アクティブ化）＋ Core Animation (`CALayer`) | 小さな透過ウィンドウを動かす方式は CPU・メモリが最小。SpriteKit は 2D スプライトの切替のみなら不要 |
| 設定・会話画面 | SwiftUI | 標準的な UI を少ないコードで |
| ウィンドウ検出 | `CGWindowListCopyWindowInfo` | 位置（bounds）は**画面収録の許可なし**で取得可能。名前・内容は取得しない |
| 背景透過素材 | Vision `VNGenerateForegroundInstanceMaskRequest` | 純正 API で資料から高品質に切り抜ける |
| 自動起動 | `SMAppService.mainApp` | macOS 13+ の正式なログイン項目 API |

### 実現可能性

| 機能 | 判定 | 補足 |
|---|---|---|
| 透過・枠なし常駐、全 Spaces・フルスクリーン上に表示 | ◎ | `collectionBehavior` で対応 |
| 透明部分のクリック透過 | ◎ | 非不透明ウィンドウの透明ピクセルはウィンドウサーバーが背面へ通す |
| ドラッグ・クリック・ダブルクリック・右クリック | ◎ | アプリをアクティブにしない（作業中のアプリのフォーカスを奪わない） |
| 複数ディスプレイ | ◎ | 同じ高さで隣接する画面は歩いて渡れる |
| ウィンドウの上に立つ・座る・飛び降りる | ◎ | ウィンドウ上端を足場化。手前のウィンドウに隠れた部分は足場から除外 |
| ウィンドウ移動への追従・閉じたら落下 | ◎ | 1 秒ごとに再取得（ポーリング） |
| ウィンドウ縁にぶら下がる | ○ | ロジック実装済み。**素材待ち** |
| 画面端を登る | ○ | ロジック実装済み。**素材待ち** |
| ウィンドウの側面を登る | △ | 窓の下端が床から浮いていることが多く、到達経路の設計が必要。次段階 |
| ウィンドウを動かす（しめじの「窓を投げる」） | × | アクセシビリティ権限が必要で他アプリの操作になる。採用しない |
| 他アプリのウィンドウより奥に隠れる | × | 鈴は常に `.floating` レベル。窓の裏に回る表現は不安定なため採用しない |

## 3. アーキテクチャ

```
SuzuApp (AppKit / SwiftUI)                    ← 表示・入力・OS 連携
 ├─ AppDelegate         ループ(モニターのリフレッシュレート)、メニュー、設定、各部の接続
 ├─ MascotPanel/View    透過ウィンドウ、スプライト描画、マウス入力
 ├─ EnvironmentSensor   画面・ウィンドウ → Terrain
 ├─ SpriteStore         manifest.json と PNG の読み込み
 ├─ Settings / Conversation / SpeechBubble
 │
SuzuCore (純粋ロジック・AppKit 非依存・単体テスト対象)
 ├─ Terrain             床（画面下端・窓の上端）と壁、遮蔽計算
 ├─ Sprites             Pose × Facing → 画像の解決とフォールバック、不足素材の列挙
 ├─ Behavior            行動定義（重み・時間・クールダウン・場所）と状況補正付き抽選
 └─ MascotSimulation    状態機械＋物理（歩行・落下・登攀・ぶら下がり・ドラッグ）
 │
SuzuBridge (鈴秘書との境界)
 ├─ SecretaryBridge     プロトコル（差し替え可能）
 ├─ NullSecretaryBridge
 └─ DistributedNotificationBridge  ローカル最小実装（JSON）
```

### 行動の自然さ（完全ランダムにしない仕組み）

- **重み付き抽選＋状況補正**：元気度（時間で減り、睡眠で回復）、時刻（深夜は眠りやすい、朝は伸びをしやすい）、場所（窓の上では座りやすい・飛び降りる）。
- **連続抑制**：同じ行動の連続は確率を下げ、歩いた後は休みやすい。
- **クールダウン**：睡眠・伸び・登攀などは一度行うとしばらく選ばれない。
- **素材による制御**：画像がない行動は選ばれない。素材を追加すると自動で行動が増える。
- **マウスへの反応**：近くにカーソルがあるとそちらを向き、鈴の上に留まると「♡」「?」で気付く。

### アニメーション方式と将来の Live2D 移行

描画は `Pose`（姿勢）・`Facing`（向き）・`Emote`（記号）という抽象状態だけを受け取り、画像の選択は `SpriteCatalog` が担う。
Live2D 等へ移行する際は描画層（`MascotView`）を差し替え、`Pose` をモーション名へ対応付けるだけでよく、行動・物理ロジックは変更不要。

## 4. 鈴秘書との連携

`SecretaryBridge` プロトコル越しにのみやり取りする。現在は `DistributedNotificationCenter` による最小実装。

- 鈴秘書 → 鈴: 通知名 `jp.suzu.secretary.event`、object に JSON 文字列
  - `{"type":"notify","title":"…","body":"…"}` 吹き出しで通知
  - `{"type":"speak","text":"…"}` 吹き出し＋会話画面に表示
  - `{"type":"expression","pose":"joy","duration":3}` 表情・反応
  - `{"type":"activity","hint":"userFocused"}` 集中中・会議中は静かにする（`userFocused|userIdle|userAway|meeting|breakTime`）
- 鈴 → 鈴秘書: 通知名 `jp.suzu.mascot.event`（`click` / `conversation` / `message`）
- 動作確認: `swift tools/send_event.swift '{"type":"speak","text":"おつかれさま"}'`

本格連携時は XPC やローカル WebSocket の実装を追加し、`AppDelegate` の生成箇所を差し替える。

## 6. 品質面

- 描画はモニターのリフレッシュに合わせる（macOS は CADisplayLink、Windows は DwmFlush）。設定で上限 fps を指定可。ほかは 1 秒ごとの窓取得のみ。画面スリープ中は停止。
  実測（Apple Silicon、release ビルド）: CPU 0.3〜0.8%、RSS 約 72〜85MB。
- 画像は起動時に一度だけ読み込み、`CALayer.contents` の差し替えのみ（毎フレームの描画処理なし）。
- 位置はピクセル境界に丸めて配置（にじみ防止）。Retina・表示倍率は `backingScaleFactor` に追従。
- 位置は 30 秒ごとと終了時に保存し、再起動時に復元。画面構成が変わっても画面内に戻す。

## 7. ビルドと実行

```sh
swift test                      # 単体テスト
swift run Suzu                  # 開発実行
scripts/build_app.sh            # build/Suzu.app を作成
open build/Suzu.app
```

操作：クリックで反応／ドラッグで移動・放り投げ／ダブルクリックで会話画面／右クリック・メニューバーの鈴アイコンでメニュー。

アプリ操作：Dock のアイコン（クリックでコントロールパネル、右クリックで起動/停止・呼ぶ）、コントロールパネル（鈴の起動・停止、一時停止、ログイン時起動、終了）、⌘Q で終了。
「鈴を止める」はアプリを動かしたまま鈴だけを消してタイマーも止める。停止状態は保存され、次回起動時も停止のまま（パネルが開く）。
⌘H でアプリを隠しても鈴本体は隠れない（`canHide = false`）。

## 8. Windows 版とインストーラー

### 構成

| 層 | macOS 版 | Windows 版（`windows/`） |
|---|---|---|
| 行動・物理・地形・スプライト解決 | `SuzuCore`（Swift） | `Suzu.Core`（C# / .NET 8、ロジックを 1 対 1 で移植。同じ単体テストを `Suzu.Core.Tests` に移植） |
| 連携 JSON | `SuzuBridge` | `Suzu.Core/SecretaryEvents.cs`（形式は同じ） |
| 透過ウィンドウ | `NSPanel`＋`CALayer` | Win32 レイヤードウィンドウ（`UpdateLayeredWindow`、乗算済みアルファの DIB に GDI+ で描画） |
| クリック透過・フォーカス | 透明ピクセルは背面へ／非アクティブ化パネル | 透明ピクセルは背面へ（レイヤードウィンドウの仕様）／`WS_EX_NOACTIVATE`・`MA_NOACTIVATE` |
| ウィンドウ検出 | `CGWindowListCopyWindowInfo` | `EnumWindows`（Z オーダー順）＋`DWMWA_EXTENDED_FRAME_BOUNDS`。最小化・非表示・別の仮想デスクトップ（cloaked）・ツールウィンドウ・最前面ウィンドウは除外。タイトルや中身は読まない |
| アプリの入口 | Dock・メニューバー | 通知領域（タスクトレイ）のアイコン |
| 設定 | `UserDefaults` | `%APPDATA%\Suzu\settings.json` |
| ログイン時に起動 | `SMAppService` | `HKCU\...\CurrentVersion\Run`（インストーラーの「サインイン時に起動」と同じ値） |
| 鈴秘書との連携 | `DistributedNotificationCenter` | 名前付きパイプ（同じユーザーのみ接続可、1 行 1 イベント） |
| 二重起動 | — | ミューテックス `SuzuDesktopMascot`。2 つ目の起動は既存の鈴のコントロールパネルを開く |

座標：`Suzu.Core` は macOS と同じ「左下原点・y 上向き」で計算し、Windows の画面座標（左上原点）とは y の符号を反転して変換する。
単位は物理ピクセル（PerMonitorV2）。鈴のいる画面の拡大率を `Config.SpeedScale` と体の大きさに掛け、拡大率が違う画面へ移ると大きさ・速さを合わせ直す。
